# SEM-EDS 미세먼지 입자 분석 대시보드

SEM 이미지와 EDS 원소 분석 데이터를 입자 단위로 통합해서 다음을 분석하는 브라우저용 연구 대시보드입니다.

- 개별 입자의 형태학적 특징
- 원소 조성비
- 입자 유형 후보와 잠재적 발생원 후보
- 위해성 평가 대상 원소의 분포

천안아산역·아산역 일대 철도·교통 환경 시료의 분석을 염두에 두고 설계했습니다. **실제 데이터가 없으면 결과를 만들어 내지 않습니다.**

> **DEMO 데이터 주의** — 앱에 들어 있는 DEMO 데이터(`public/sample-data/`)는 화면 흐름을 보여주려고 고정 시드로 생성한 **가상 예시**입니다. 실제 측정 결과가 아니므로 어떤 실제 시료(천안아산역·아산역·강남역 등)의 결과로도 사용·인용할 수 없습니다. DEMO 상태에서는 다음 위치에 `DEMO·가상` 표시가 붙습니다.
> - 화면 상단 빗금 배너
> - 모든 KPI와 차트
> - 내보낸 CSV·PNG·보고서
> - 합성 이미지 워터마크

모든 처리는 브라우저 안에서만 이루어집니다. 업로드한 파일은 외부로 전송되지 않으며 서버나 데이터베이스도 없습니다.

## 1. 실행 방법

필요 환경은 **Node.js 20 이상**입니다(개발 환경: Node 24, npm 11).

```bash
cd sem-particle-analyzer/dashboard
npm install          # 처음 한 번
npm run dev          # 개발 서버 → http://localhost:5173
```

| 명령 | 내용 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm test` | 계산 로직 테스트 실행(Vitest) |
| `npm run build` | 타입 검사 후 정적 파일을 `dist/`로 빌드 |
| `npm run preview` | 빌드 결과를 로컬 서버로 확인 |
| `npm run build:offline` | 오프라인판(HTML 파일 하나) 생성 → `dist-offline/` 및 상위 작업 폴더에 복사 |
| `npm run shared:set -- "<백업.json>"` | 팀 공유 데이터셋 지정(배포판에 데이터 포함) |
| `npm run shared:clear` | 팀 공유 데이터셋 빼기 |
| `npm run generate:demo` | DEMO CSV 다시 생성 |

> `index.html`을 더블클릭해도 열리지 않습니다. React+TypeScript(Vite) 프로젝트라 개발 서버나 정적 서버를 거쳐야 합니다.
>
> `dist/`는 `base: "./"`로 빌드되므로 아무 정적 서버(`npx serve dist`)나 GitHub Pages 하위 경로에 그대로 올릴 수 있습니다. 다만 `file://`로 직접 열면 DEMO·템플릿 파일을 불러오지 못합니다.

### 바로 여는 방법 두 가지

| 방법 | 파일(상위 `미래설계 대시보드` 폴더) | 필요 조건 |
|---|---|---|
| 실행 파일 | `SEM-EDS 대시보드 열기.bat` 더블클릭 → 서버를 켜고 브라우저로 열기(처음 한 번 패키지 자동 설치) | Node.js |
| **오프라인판** | `SEM-EDS 대시보드 (오프라인).html` 더블클릭 | 브라우저만(Chrome·Edge 권장). 인터넷·서버·Node.js 불필요 |

오프라인판은 JS·CSS·DEMO 데이터·입력 템플릿·TIFF 디코더를 모두 HTML 파일 하나(약 1.4 MB)에 넣은 것입니다. 기능은 일반판과 같으며, 파일을 USB나 메일로 전달해도 그대로 열립니다.

- 인터넷이 없으면 IBM Plex 글꼴 대신 시스템 글꼴(맑은 고딕)로 표시됩니다.
- 설정·규칙 저장(`localStorage`)은 파일 위치마다 따로 관리됩니다. 파일을 옮기면 설정이 초기화될 수 있으니, 필요한 설정은 내보내기로 보관하세요.
- 코드를 고친 뒤에는 `npm run build:offline`으로 다시 만들어야 반영됩니다.

### 팀원과 결과 공유하기(GitHub 배포)

등록·분석한 데이터는 각자의 브라우저에만 저장됩니다. 팀원에게 같은 결과를 보여주려면 **백업 파일을 배포판에 넣어** GitHub에 올립니다.

1. 대시보드 **데이터 업로드 → 데이터 보관 → 백업 파일 저장**으로 `SEM-EDS_backup_날짜.json`을 받습니다.
2. 이 폴더에서 아래 명령을 실행합니다. 백업 파일이 `public/shared-data/dataset.json`으로 복사됩니다. DEMO 데이터 백업은 거부하며, 흑백 SEM 이미지는 픽셀 값이 같은지 확인한 뒤 8비트 회색조 PNG로 **무손실** 변환해 크기를 줄입니다(입자 20개 기준 67 MB → 30 MB).

   ```bash
   npm run shared:set -- "C:\Users\...\Downloads\SEM-EDS_backup_2026-10-12.json"
   ```

3. 커밋하고 `main` 브랜치에 push합니다. GitHub Actions(`.github/workflows/deploy-pages.yml`)가 테스트·빌드 후 GitHub Pages에 배포합니다.
   - `https://<계정>.github.io/<저장소>/` — 웹판. 처음 여는 팀원에게 공유 데이터셋이 바로 보입니다(상단 "팀 공유 데이터셋 · 날짜 기준" 표시).
   - `.../offline.html` — 공유 데이터가 **들어 있는** 오프라인판. 사이드바의 "오프라인판 내려받기"로 받아 더블클릭으로 엽니다.
   - `.../legacy/` — 기존 단일 이미지 분석기
4. 처음 한 번은 저장소 **Settings → Pages → Source를 "GitHub Actions"**로 설정해야 합니다.

데이터를 더 등록한 뒤에는 1–3을 반복하면 배포판이 새 스냅샷으로 바뀝니다. 공유 스냅샷을 보기만 하는 팀원의 브라우저에는 저장하지 않으므로, 새 배포가 나오면 그대로 반영됩니다. 팀원이 그 위에 입자를 등록하거나 고치면 그때부터는 그 팀원의 "내 데이터"로 자동 저장됩니다. 공유 데이터셋은 "데이터 보관"에서 언제든 다시 열 수 있습니다.

로컬에서 오프라인 HTML에 공유 데이터를 넣으려면 `npm run shared:set` 후 `npm run build:offline`을 실행하세요.

> **공개 범위 주의**: 공개(Public) 저장소와 GitHub Pages에 올린 SEM 이미지·EDS 결과는 누구나 볼 수 있습니다. `tests/fixtures/phenom_*`(실측 CSV·메타데이터·이미지 일부)도 저장소에 포함됩니다.

## 3. 실제 데이터 입력 방법

### 기본: 입자 등록 — SEM 이미지 1장 + EDS 정량 파일 1개 = 입자 1개

입자 하나를 찍은 SEM 사진과, 그 입자를 분석한 EDS 정량 파일을 한 쌍으로 등록합니다. **데이터 업로드** 화면 맨 위의 "입자 등록"에 두 파일을 함께 끌어 놓으세요. 여러 입자를 한꺼번에 올려도 됩니다.

| 파일 | 예시 | 대시보드가 읽는 내용 |
|---|---|---|
| SEM 이미지 | `261008_Local1 (2).tiff` (Phenom TIFF) | 파일 안의 장비 메타데이터(XML): 픽셀 크기(µm/px), 배율, 시야폭, 촬영 시각, 가속전압, 검출기, WD, 하단 정보바 높이 |
| EDS 정량 파일 | `quantification (1).csv` (Phenom 내보내기) | `Element symbol`, `Atomic concentration percentage`, `Weight concentration percentage` — 0–1 분수(합계 1)는 ×100 하여 %로 환산, wt%·at% 따로 저장 |

등록 순서:

1. **짝짓기** — 이미지마다 한 행을 만들고, CSV를 파일 수정 시각 순서대로 짝 없는 행에 붙입니다. 장비 내보내기 파일에는 입자 ID가 없어 파일 내용만으로는 짝을 알 수 없으므로, 각 행의 "EDS 정량 파일" 목록에서 **짝이 맞는지 꼭 확인**하세요(원소 미리보기가 함께 표시됩니다).
2. **자동 입력** — 시료 ID(이미지 정보바 라벨, 예: `261008_Local`. 다음부터는 마지막 입력값), 입자 ID(`P001`부터 빈 번호), 채취일(촬영 시각), 픽셀 크기(장비 메타데이터)를 채웁니다. 채취 지점·시료 유형은 마지막 입력값을 기억합니다. 모두 고칠 수 있습니다.
3. **형상 측정** — 이미지에서 입자 하나를 자동으로 분할해 등가원 지름·최대 Feret 지름·투영 면적(µm)과 원형도·고형도·종횡비를 계산하고, 측정 윤곽(파란 선)을 사진에 겹쳐 보여줍니다. 윤곽이 입자 외곽과 맞을 때 "윤곽이 입자 외곽과 맞음"을 체크해야 크기·형상 지표가 저장됩니다. 맞지 않으면 임계 계수 슬라이더를 움직여 다시 측정하세요.
4. **형상 판정** — 사진을 보고 직접 고릅니다. 측정 지표가 구형·섬유상·응집체 조건에 해당하면 "후보"를 제안하지만 자동으로 적용하지 않습니다.
5. **등록** — 오류(✕)가 없는 행만 등록됩니다. 같은 시료 ID·입자 ID가 이미 있으면 새 값으로 바뀝니다(경고 표시).

장비 메타데이터가 없는 이미지(JPG·PNG 등)는 픽셀 크기(µm/px)를 직접 입력하면 µm 크기를 계산합니다. 입력하지 않으면 원형도 같은 무차원 지표만 저장하고 µm 크기는 계산하지 않습니다.

#### 이미지 형상 측정 방법

처리 순서는 다음과 같습니다.

1. 하단 정보바 제외(Phenom 메타데이터의 정보바 높이, 없으면 자동 감지)
2. 가우시안 블러(σ 3 px)
3. 임계값 = Otsu × 0.7(기본값, 화면에서 조절)
4. 닫힘 연산(6 px)과 구멍 채우기
5. 가장 큰 영역 하나를 입자로 선택

전역 Otsu 임계값을 그대로 쓰면 입자 안쪽의 그늘진 면이 배경으로 잘려 윤곽이 들쭉날쭉해집니다. 보내주신 실측 이미지에서 원형도 0.13, 고형도 0.71로 크게 과소평가되는 것을 확인했습니다. 계수 0.7과 닫힘 연산을 쓰면 외곽을 따라가며, 해당 이미지의 결과는 등가원 지름 4.52 µm, 최대 Feret 5.68 µm, 고형도 0.90입니다. 이 계수는 이미지 한 장에서 정한 값이므로 **윤곽 확인을 거쳐야** 저장되도록 했습니다. 측정 방법과 파라미터는 `size_method`에 기록됩니다.

#### 데이터 보관

- **자동 저장**: 등록한 입자(이미지 포함)는 이 브라우저의 IndexedDB에 자동 저장되어, 창을 닫거나 새로고침해도 다시 열면 복원됩니다. 저장 위치는 그 브라우저와 그 주소(또는 그 HTML 파일)에 한정되며, DEMO 데이터는 저장하지 않습니다.
- **백업 파일**: "백업 파일 저장"으로 데이터셋 전체(이미지·설정·규칙 포함)를 `.json` 하나로 내보내고, 다른 PC나 팀원 브라우저에서 "백업 파일 불러오기"로 엽니다. 브라우저 데이터 삭제에 대비해 정기적으로 백업하세요.
- "데이터 비우기"는 자동 저장본까지 지웁니다.

### 고급: 여러 입자 일괄 업로드(ID 열이 있는 표)

**데이터 업로드** 화면의 "여러 입자 일괄 업로드(고급)"를 펼쳐 CSV·XLSX와 이미지 파일을 끌어 놓습니다. 결과 내보내기의 "입자 메타데이터 CSV"와 "정리된 EDS(긴 형식) CSV"도 이 방식으로 다시 불러올 수 있습니다.

- 표 종류는 열 구성으로 자동 판별하며, 필요하면 직접 지정할 수 있습니다.
- XLSX는 시트마다 따로 판별합니다.
- 화면에서 템플릿을 내려받을 수 있습니다(원본: `public/templates/`, 앱 번들에도 포함되어 오프라인판에서도 내려받기 가능).
- 템플릿의 `#`로 시작하는 줄은 설명이며 불러올 때 무시됩니다.
- 측정값이 없는 칸은 **비워 두세요.** 임의 값을 넣지 마세요.

### B. EDS 원소 조성 — 긴 형식 권장 (`eds_long_template.csv`)

한 행에 한 입자의 한 원소를 적습니다.

| 열 | 설명 |
|---|---|
| `sample_id`, `particle_id` | 메타데이터와 같은 표기여야 연결됩니다 |
| `element_symbol` | Fe, FE, Fe K, Fe-Ka, Iron, 철 → 모두 Fe로 표준화 |
| `wt_percent`, `at_percent` | **따로 기재.** 없는 값은 비워 둡니다. 대시보드는 둘을 서로 환산하지 않습니다 |
| `detection_status` | `detected` / `below_loq` / `below_lod` / `not_detected`(검출, ND, <LOD 같은 표기도 인식) |
| `detection_limit`, `quantification_limit` | wt% 단위로 가정 |
| `measurement_method` | 정량 방법(표준없는 정량, ZAF 등) |
| `normalized` | 원자료가 100%로 정규화된 값이면 Y, 아니면 N |

열 이름 별칭도 인식합니다(예: `Weight %`, `Atomic concentration percentage`, `Element symbol`, `입자 ID`).

**넓은 형식**(한 행 = 한 입자)도 읽습니다. 원소 열 이름에 기준을 붙이세요: `Fe_wt`, `Fe_at`, `Fe wt%`. 기준 표시가 없는 열(`Fe`)은 행마다 `basis` 열(wt%/at%)이 있어야 읽고, 없으면 **오류로 거부**합니다.

### 검출 상태 결정 규칙

결정 순서는 다음과 같습니다.

1. `detection_status` 열에 명시된 값
2. 값 칸의 문자 표기 — `ND` → 미검출, `<LOD` → 검출한계 미만, `<LOQ` → 정량한계 미만, `<0.1` → 검출한계 미만(한계 0.1), `NA`·`-` → 결측
3. `detection_limit`·`quantification_limit`와 wt% 값 비교
4. 상태 정보가 없으면 값 > 0은 검출, 값 = 0은 미검출로 **추정**(추정했다는 사실을 기록·표시)
5. 빈칸은 **결측** — 미검출과 구분합니다

명시된 상태와 값이 어긋나면(예: 상태는 미검출인데 값이 양수) 상태를 우선하고 경고합니다.

### C. 위해성 평가 규칙 (`hazard_rules_template.csv`)

열 구성: `element_symbol, assessment_category, reference_name, reference_year, reference_url, applicable_condition, classification_note`

- 출처와 적용 조건을 함께 기록해야 합니다.
- 업로드하면 설정의 규칙을 대체합니다.

### D. 선택 데이터

**PM 측정값** (`pm_measurements_template.csv`): `sample_id, collection_location, collection_date, pm25, pm10, unit, measurement_method, source`

PM 값은 **보고값으로만** 표시하며, 입자 분석 결과와 합산하거나 환산하지 않습니다.

### SEM 이미지

JPG·PNG·TIFF·BMP를 지원합니다. TIFF는 브라우저에서 직접 디코딩하고, 16비트 회색조는 값 범위에 맞춰 8비트로 펴며 그 사실을 표시합니다.

입자와 연결하는 순서는 다음과 같습니다.

1. 메타데이터 `image_filename`과 파일명 일치(대소문자 무시)
2. 확장자를 뺀 이름 일치(`S01_P001.tif` ↔ `S01_P001.png`)
3. 메타데이터에 파일명이 없으면 `시료ID_입자ID` 또는 입자 ID와 같은 파일명. 단, 입자 ID가 여러 시료에 중복되면 입자 ID만으로는 연결하지 않습니다

연결되지 않은 이미지·입자는 **미매칭 목록**에 표시됩니다.

### 업로드 시 수행하는 검사

- 파일 형식·인코딩(UTF-8 / EUC-KR 자동 판별)·필수 열
- 결측값, 숫자로 읽을 수 없는 값, 0–100 범위 밖의 값
- 중복 입자 ID(메타데이터), 중복 입자·원소(EDS)
- 스케일·크기 단위 인식과 환산
- wt%/at% 기준 불명확 열 거부
- 0–1 분수로 기재된 파일 감지: 모든 입자 합계가 1 근처이면 ×100 환산 후 경고
- 입자별 조성 합계가 100 ± 허용범위(기본 5%p)를 벗어나는지. 정규화 여부를 함께 표시
- 측정 방법이 섞였는지
- 메타데이터 ↔ EDS ↔ 이미지 연결

같은 입자의 EDS가 다른 파일에서 다시 들어오면 두 파일 값을 섞지 않고 새 파일 값으로 **통째로** 바꿉니다.

## 4. 계산식과 분모

| 지표 | 정의 |
|---|---|
| 유효 EDS 분석 입자 | EDS 기록이 있고, 모든 값이 결측이 아니며, 제외 조건(사용자 제외, 선택 시 합계 이탈)에 해당하지 않는 입자 |
| **대상 원소 검출 입자 비율(%)** | 대상 원소가 하나 이상 검출된 입자 수 ÷ 판정 가능한 유효 입자 수 × 100 |
| 판정 가능 입자 | 대상 원소가 검출된 입자 + 모든 대상 원소가 판정 가능(결측 없음)하면서 미검출인 입자. 대상 원소가 검출되지 않았는데 일부가 결측이면 **판정 불가**로 분모에서 제외 |
| 원소별 검출 빈도 | 그 원소가 검출된 입자 ÷ 그 원소를 판정할 수 있는 유효 입자(원소별 분모) |
| k개 이상 동시 검출 비율 | 검출 수 ≥ k → 양성, 검출 수 + 결측 수 < k → 음성, 나머지는 판정 불가(분모 제외) |
| 원소 조성 통계 | 상태가 '검출'이고 해당 기준 값이 있는 입자만 사용. LOQ 미만은 정량 통계에서 제외. wt%와 at%는 따로 계산 |
| 평균 조성(도넛) | 해당 기준 값이 있는 유효 입자의 입자별 조성 산술평균(미검출 = 0) — **질량 가중 평균이 아님** |
| 신뢰구간 | 비율의 Wilson 95% 신뢰구간 |
| 상관 | Spearman(기본) 또는 Pearson. 두 원소 모두 판정 가능한 입자만 사용하며, 미검출·LOD 미만은 0, LOQ 미만·결측은 제외. n < 5면 계산하지 않음. 조성 자료의 폐쇄성(합 100) 주의 |
| 그룹 비교 | Fisher 정확검정(양측) + Holm 보정. 각 그룹 3개 이상일 때만 |

한 입자에서 여러 대상 원소가 검출되어도 입자 개수 비율에서는 **1개로** 셉니다.

### 계산하지 않는 지표 (항상 "분석 불가")

다음 지표는 이 대시보드에서 계산하지 않습니다.

- 전체 미세먼지 질량 중 대상 원소의 **질량 비율** — 입자별 질량(밀도×부피), 대표성 있는 시료 선정 설계, 질량 가중 정량 자료가 없기 때문입니다
- **PM2.5/PM10 대기 농도** — 채취 유량·시간과 중량 측정 자료가 필요합니다
- **인체 노출량·건강 위해도** — 화학종, 생체 이용률, 노출 정보가 필요합니다

입자별 wt%만으로 전체 대기 미세먼지 중 유해 성분의 질량 비율을 계산하지 않습니다.

## 5. 분류·발생원 규칙과 위해성 평가 기준

### 형상 분류

형상은 다음 중 하나로 정해집니다.

- 메타데이터의 판정값
- 입자 상세 화면에서 사용자가 입력한 판정값

**이미지 기반 형상 지표 측정**은 기존 `sem-particle-analyzer`의 영상처리 파이프라인(`src/lib/image/ip.js`, 알고리즘 변경 없음)을 씁니다. 처리 순서는 다음과 같습니다.

1. Otsu 이진화
2. 연결성분 분석
3. 원형도·고형도·종횡비·Feret 지름 계산

측정 결과로는 형상 **후보**만 제안하며, 적용 여부는 사용자가 결정합니다.

- 각진 파편형·판상형·다공성/불규칙형은 2D 윤곽 지표로 구분하지 않습니다.
- 스케일 보정값이 없으면 실제 크기(µm)를 계산하지 않습니다.

### 입자 유형·발생원 후보 (규칙 기반)

규칙은 코드와 분리된 `src/config/classificationRules.default.json`에 있습니다. **분석 설정** 화면에서 JSON으로 편집·검사·적용·내보내기할 수 있습니다.

- 조건 종류: `min`, `max`, `sumMin`, `sumMax`, `ratioBetween`, `detected`, `anyDetected`, `morphologyIn`, `requiresBackground`
- 임계값은 모두 wt% 기준입니다.
- 정규화는 금속기준(C·O 제외 재정규화)과 전체기준 중에서 고릅니다.
- 입자 유형 임계값은 기존 프로토타입 규칙 v2 기본값(**합성 데이터로 정한 값**)이므로 실측 시료로 재보정해야 합니다.
- "비철 금속" 후보의 임계값(Cu+Zn+Ni+Cr+Pb+Sn ≥ 10 wt%)은 근거 문헌이 없는 탐색용 기본값이며, 화면에도 그렇게 표시됩니다.

발생원 후보마다 다음을 표시합니다.

- 판단에 활용한 원소·형태 특징
- 실제 데이터에서 확인된 근거
- 보조 근거와 확인되지 않은 보조 근거
- 대안적 설명
- 판단 수준(원소 조건만 / 원소 + 보조 근거)
- 추가 검증 데이터

**확정**으로 표시하는 경우는 없습니다. 예를 들어 Fe 검출만으로 철도 마찰 분진이라고 하지 않습니다. "외부 대기 유입"은 개별 입자로 판별할 수 없으므로 항상 판별 불가(배경 시료 비교 필요)로 표시합니다.

통계 기반이나 머신러닝 기반 자동 분류는 **구현하지 않았습니다.**

### 원소별 건강 영향 참고 정보

위해성 관련 원소 분포 화면의 "원소별 위해 정보와 검출 입자"는 원소를 고르면 다음을 함께 보여줍니다.

- 노출 시 알려진 건강 영향과 주요 표적 장기, 화학종·적용 조건, 출처
- 그 원소가 검출된 입자들의 함량 분포도(입자별 wt%/at%)
- 해당 입자의 SEM 사진과 입자별 조성 막대(고른 원소 강조)

건강 영향 문구는 WHO·IARC·미국 ATSDR·NIOSH 등 공개 기관 자료를 짧게 요약한 기본 참고 정보입니다(`src/config/healthInfo.ts`). 대상 원소 10개와, 실측 데이터에서 검출된 참고 원소 Si·Mo·Al·Sr이 들어 있습니다. 근거를 확인하지 못한 원소(C·O·N·F·Ca·Y 등)는 내용을 만들지 않고 "등록된 정보 없음"으로 표시합니다.

**분석 설정**의 위해성 평가 규칙 표에 있는 `target_organs`, `health_effects`, `health_references`("이름 | URL ; 이름 | URL") 열에서 고칠 수 있고, 비워 두면 기본 참고 정보를 씁니다. 이 정보는 원소(또는 특정 화학종)에 **노출되었을 때**의 일반적 영향입니다. 입자에서 원소가 검출되었다는 사실이 그 위해를 뜻하지 않으며, 화면에도 그렇게 표시합니다. 사용 전 원문을 확인하세요.

EDS 원소 분포 영상(매핑)은 현재 입력 데이터에 없어 표시하지 않습니다.

### 위해성 평가 규칙 기본값

출처를 확인할 수 있는 **IARC 발암성 분류**만 채웠습니다.

| 원소 | 범주 | 출처 |
|---|---|---|
| As | Group 1 | Vol. 100C, 2012 |
| Cd | Group 1 | Vol. 100C, 2012 |
| Cr | Cr(VI) 화합물에 한해 Group 1 | Vol. 100C |
| Ni | 화합물 Group 1 / 금속 Group 2B | Vol. 100C / Vol. 49 |
| Pb | 무기 화합물 Group 2A / 금속 Group 2B | Vol. 87, 2006 |

나머지 원소(Co, Mn, Cu, Zn, Fe)는 `평가 대상(범주 미입력)`으로 두었습니다.

IARC 분류는 **화학종** 기준이고 EDS는 화학종을 구분하지 못합니다. 그래서 이 범주는 원소별 참고 정보로만 표시하며 입자의 위해도 판정에는 쓰지 않습니다. 사용 전에 원문(https://monographs.iarc.who.int/list-of-classifications/)을 확인하세요.

## 7. 내보내기

**분석 설정·결과 내보내기** 화면에서 할 수 있습니다. 결과는 현재 필터 기준입니다.

CSV는 UTF-8 BOM으로 저장해 엑셀에서 한글이 깨지지 않습니다. 파일 머리 주석(`#`)에 다음을 기록합니다.

- 데이터 구분(DEMO/실측)
- 대상 원소와 계산 가정
- 필터

| 내보내기 | 형식 |
|---|---|
| 입자별 분류·검출 결과(크기·형상 지표·촬영 조건 포함) | CSV |
| 입자 메타데이터(다시 불러오기 가능) | CSV |
| 원소 조성 요약표 | CSV |
| 대상 원소 검출 현황(평가 범주·출처 포함) | CSV |
| 시료별·채취 지점별 비교 | CSV |
| 정리된 EDS(긴 형식) | CSV |
| 품질 검사 결과 | CSV |
| 그래프 | 각 차트의 PNG 버튼(제목·기준·DEMO 표시 포함) |
| 요약 보고서 | 새 창에서 인쇄 → PDF 저장, 또는 HTML 내려받기 |

요약 보고서에는 데이터 범위, 분석 입자 수, 계산식, 주요 결과, 계산하지 않은 지표, 분석 한계와 주의사항, 추가 조사 항목이 들어갑니다.

### 데이터 보관

- 등록·업로드한 데이터는 브라우저(IndexedDB)에 자동 저장되며, 백업 파일(.json)로 옮길 수 있습니다(3장 "데이터 보관").
- 설정·위해성 규칙·분류 규칙·형상 판정 수정값은 브라우저 `localStorage`에 저장됩니다.

## 8. 테스트

```bash
npm test
```

테스트 108개가 검증하는 항목:

- 원소 조성비 집계
- wt%·at% 비혼합(서로 채우지 않음, 통계 분리)
- 결측과 미검출의 구분
- ND·<LOD·<LOQ 해석, 한계값 비교
- 입자별 분모와 원소별 분모
- 복수 대상 원소가 있어도 입자 수가 중복 계산되지 않음
- 판정 불가 처리, 설정 변경 시 분모 변화
- 필터 변경 시 KPI·차트 데이터 일관성
- SEM 이미지–입자 ID 매칭(대소문자, 확장자, 중복 입자 ID)과 미매칭 목록
- 데이터가 없을 때 허위 결과가 나오지 않음(비율 null)
- DEMO/실측 구분(파서, 입자, 내보내기, 보고서)
- 질량 비율·대기 농도·건강 위해도를 계산하지 않음
- wt% 없을 때 분류하지 않음, 스케일 없을 때 크기를 계산하지 않음
- 근거 없는 위해 범주가 없음
- 통계 함수(Fisher·Wilson·Holm·Spearman 기준값)
- 인코딩(EUC-KR)과 XLSX
- 보고서 구성
- 원소별 건강 영향 정보: 대상 원소 전체에 출처 포함, 사용자 입력 우선·기본값 대체, 근거 없는 원소는 내용 없음, 출처 분리
- **실측 Phenom 파일**: TIFF 메타데이터(픽셀 크기·배율 20,000×·시야폭 25.9 µm·10 kV·SED), 정량 CSV의 분수→% 환산과 wt/at 분리, 입자 등록·결합·분류, 실측 이미지 단일 입자 분할(크기 범위), 메타데이터 CSV 왕복

`tests/fixtures/test_*.csv`는 **계산 검증용 가상 데이터**입니다. `tests/fixtures/phenom_*`은 연구팀이 제공한 **실측 파일**(Phenom EDS 정량 CSV, TIFF 메타데이터 XML, 입자 주변 600×600 영역 회색조)입니다.

분석 로직(`src/lib`)은 React에 의존하지 않습니다. 나중에 Python 기반 이미지 분석이나 머신러닝 모듈을 붙일 때는 결과를 같은 형식으로 넣으면 됩니다.

- 형상: 메타데이터 CSV의 `morphology_class` + `classification_method`
- 크기: `projected_area`·`equivalent_diameter`

## 10. 기존 도구와의 관계

상위 폴더의 `docs/`(SEM 입자 분석기, 단일 이미지용 바닐라 JS)는 그대로 유지했습니다. 이 대시보드는 그 영상처리 파이프라인과 조성 규칙 v2 기본값을 재사용하고, 여러 시료·입자를 모아 분석하는 기능을 추가로 담당합니다.

기술 스택: React 19, TypeScript, Vite, Tailwind CSS 4, Recharts, Papa Parse, SheetJS(xlsx 0.20.3, SheetJS CDN 배포판), UTIF(TIFF), Vitest.
